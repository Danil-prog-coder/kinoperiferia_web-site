# Кинопериферия

Сайт мастерской «Кинопериферия» — аксессуары для кинопроизводства — на Go.
Функциональность перенесена с рабочего сайта, оформление — по новому макету
(тёмная «газетная» вёрстка, Source Serif 4, одна технологическая жёлтая краска).

Весь HTML собирается на сервере, внешних зависимостей нет — только стандартная
библиотека Go. Шаблоны и статика вшиты в бинарник через `go:embed`, поэтому для
запуска достаточно одного файла.

## Запуск

```bash
go run .                       # http://localhost:8080
go test ./...                  # тесты
go build -o kinoperiferia .    # сборка одного бинарника
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | порт HTTP-сервера |
| `BASE_URL` | пусто | публичный адрес сайта для canonical, Open Graph и `sitemap.xml` |
| `ORDERS_FILE` | `data/orders.jsonl` | файл заявок в формате JSON Lines; пустое значение отключает запись |
| `TELEGRAM_BOT_TOKEN` | пусто | токен бота для уведомлений о заявках |
| `TELEGRAM_CHAT_ID` | пусто | чат, куда бот шлёт заявки |
| `S3_ENDPOINT` | `https://s3.storage.selcloud.ru` | адрес S3 (у бакета Selectel свой регион) |
| `S3_REGION` | `ru-1` | регион бакета |
| `S3_BUCKET` | пусто | бакет для бэкапа |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | пусто | сервисные S3-ключи |
| `BACKUP_S3_BUCKET` | `S3_BUCKET` | отдельный бакет для бэкапа, если нужен |
| `BACKUP_S3_KEY` | `backups/kinoperiferia-data.tar.gz` | объект, который перезаписывается бэкапом |
| `BACKUP_INTERVAL_MINUTES` | `30` | период бэкапа |
| `BACKUP_RESTORE_ON_START` | `always` | восстановление при старте: `always`, `empty`, `off` |

Уведомления в Telegram включаются, только когда заданы обе переменные бота.
Без них заявки просто пишутся в файл и в лог.

## Бэкап данных в S3

Заявки (`orders.jsonl`) и вложения (`uploads/`) — единственное состояние сайта.
Когда заданы `S3_BUCKET`, `S3_ACCESS_KEY` и `S3_SECRET_KEY`, сайт хранит их копию
в S3: один архив `tar.gz`, который перезаписывается, а не копится.

* **Старт** — данные восстанавливаются из S3 *до* того, как сайт начнёт
  принимать запросы. Не восстанавливаются, если в бэкапе заявок меньше, чем
  локально (бэкап устарел после падения сервера). Режим `empty` восстанавливает
  только в пустой каталог, `off` выключает восстановление.
* **Работа** — бэкап сразу после старта и затем каждые `BACKUP_INTERVAL_MINUTES`.
  Если данные не изменились, архив не перезаливается.
* **Остановка** (SIGTERM/SIGINT: `docker stop`, перезапуск, перезагрузка) —
  сайт дожидается текущих запросов, снимает финальный бэкап и только потом
  выходит. Бэкап встроен в процесс сайта, поэтому порядок гарантирован.

Защиты: пустой каталог (0 заявок) никогда не затирает бэкап, где заявки есть;
если восстановление при старте не удалось за 3 попытки, сайт запускается, но
выгрузка в S3 отключается до перезапуска, чтобы старые данные не затёрли
облачную копию. Без настроек S3 сайт работает как раньше, без бэкапа.

S3-клиент (подпись AWS Signature V4) написан на стандартной библиотеке —
внешних зависимостей по-прежнему нет.

## Маршруты

| Маршрут | Что делает |
|---|---|
| `GET /` | главная начинается сразу с каталога; `?cat=` — категория; ниже доставка и контакты |
| `GET /catalog` | 301 на `/` (сохраняет `?cat=`) |
| `GET /product/{slug}` | страница изделия: цена, исполнения, характеристики, разметка Schema.org — под карточкой ничего лишнего |
| `GET /order` | форма заявки; `?product=` подставляет изделие |
| `POST /order` | приём заявки: проверка полей, запись в файл, уведомление в Telegram |
| `GET /api/products` | JSON-каталог; поддерживает `cat` и `sort` |
| `GET /api/products/{slug}` | JSON одного изделия (его использует быстрый просмотр) |
| `GET /sitemap.xml`, `GET /robots.txt` | для поисковых систем |
| `GET /healthz` | проверка живости и размер каталога |

Значения `cat` и `sort`: категории — `camera`, `bags`, `light`, `set` (или `all`);
сортировки — `default`, `price-asc`, `price-desc`, `name`. Неизвестные значения
молча сводятся к значениям по умолчанию.

## Как это устроено

```
main.go                 запуск, конфигурация из окружения, корректная остановка
internal/catalog        каталог изделий, фильтрация, сортировка, форматирование цен
internal/site           контакты и текстовые блоки страниц
internal/orders         проверка, хранение и отправка заявок
internal/backup         бэкап заявок и вложений в S3 и восстановление при старте
internal/server         маршруты, шаблоны, JSON API, ограничение частоты заявок
web/templates           шаблоны html/template
web/static              стили, скрипт, favicon
```

Сайт работает без JavaScript: фильтры каталога — обычные ссылки, сортировка —
форма с кнопкой, карточка изделия — отдельная страница, список изделий в
заявке — обычный select. Скрипт добавляет поверх этого фильтрацию без
перезагрузки, быстрый просмотр изделия в оверлее (данные грузятся заранее, при
наведении на карточку) и свой выпадающий список изделий с фото, ценой, группами
по разделам и поиском.

### Скорость и плавность

* шрифты Golos Text и IBM Plex Mono лежат в `web/static/fonts` — сайт не ходит
  на Google Fonts, который из России отвечает медленно;
* анимации — только `opacity` и `transform`: их браузер ведёт на видеокарте;
  размытие фона (`backdrop-filter`) осталось лишь на шапке, меню и окнах;
* фон страницы — отдельный закреплённый слой, а не `background-attachment:
  fixed`, который перерисовывал весь экран на каждом кадре прокрутки;
* ссылки на страницы предзагружаются при наведении (Speculation Rules);
* статика: CSS/JS с версией и шрифты кешируются на год, фото — на сутки с
  фоновым обновлением ещё неделю.

## Правка контента

* изделия, цены и характеристики — `internal/catalog/catalog.go`;
* контакты и тексты блоков — `internal/site/site.go`;
* оформление — `web/static/css/style.css` (токены цвета и отступов собраны в `:root`).

## Docker

```bash
cp .env.example .env           # заполнить S3 и Telegram
docker compose up -d --build   # сайт на :8080, данные в томе data
```

Или без compose:

```bash
docker build -t kinoperiferia .
docker run -p 8080:8080 -v kinoperiferia-data:/data --stop-timeout 120 \
  -e BASE_URL=https://example.ru kinoperiferia
```

`stop_grace_period: 2m` в compose (или `--stop-timeout`) даёт время на
финальный бэкап: по умолчанию Docker ждёт всего 10 секунд.
